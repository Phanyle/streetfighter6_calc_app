# SF6 対戦ログ — 試合後すぐ記録できるミニアプリ

試合が終わったら「相手キャラ → 勝ち/負け → 記録する」の 3 タップで、
Google スプレッドシートの **対戦履歴** シートに 1 行追加されるアプリです。

```
[ブラウザ / スマホ]  app/index.html
        │  POST (JSON + API キー)  ※HTTPS
        ▼
[Google Apps Script Web アプリ]  gas/Code.gs
        │  キー照合・入力チェック → appendRow
        ▼
[スプレッドシート「対戦履歴」シート]
```

## ファイル構成

| パス | 内容 |
|---|---|
| `gas/Code.gs` | スプレッドシートに紐づける Apps Script (受け口 API) |
| `gas/appsscript.json` | Apps Script のマニフェスト (権限を最小化) |
| `app/index.html` / `app.js` / `style.css` | 入力アプリ本体 (外部ライブラリなし) |

## 記録される列

既存の表「表_3」(対戦履歴シート) の空いている一番上の行に書き込みます。

| 日付 | 使用キャラクター (自分) | 使用キャラクター (相手) | 勝敗 | 結果詳細 | ポイント | 反省点・メモ | 試したこと・意識したこと | 対策 | メンタル |
|---|---|---|---|---|---|---|---|---|---|
| 2026/09/27 | テリー | ジュリ | 負け | 1-2 | 1234 | [対空][DR対応] 起き攻め通されすぎ | | | |

- 必須は **相手キャラ** と **結果** だけ。
- タグは「反省点・メモ」の先頭に `[対空]` の形で付きます。
- 結果詳細 (`1-2` など) は日付に化けないよう文字列で書き込みます。
- 1 行目の見出しが上と 1 文字でも違うと、**書き込まずにエラー**を返します (既存データを壊さないため)。
  見出しを変えたら `Code.gs` の `HEADERS` も同じに直してください。

## セットアップ手順

### 1. Apps Script を作る

1. スプレッドシートを開き、メニュー **拡張機能 → Apps Script**。
2. 左の `コード.gs` の中身を全部消して `gas/Code.gs` を貼り付ける。
3. 歯車 **プロジェクトの設定** → 「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオン。
4. エディタに出てきた `appsscript.json` を `gas/appsscript.json` の内容で置き換える。
5. 保存 (Ctrl+S)。

> `appsscript.json` の `oauthScopes` を `spreadsheets.currentonly` に絞っているので、
> このスクリプトは **このスプレッドシート 1 つにしか触れません** (ドライブ全体や他のシートは不可)。

### 2. API キーを発行する

1. コードの真上のツールバー (`▷ 実行` `デバッグ` の右) にある関数プルダウン
   (最初は `doPost` などと表示) で **`setupApiKey`** を選び、**▷ 実行** を押す。
   プルダウンに出てこないときは、先に Ctrl+S で保存する。
2. 初回は権限確認が出るので自分のアカウントで許可
   (「Google がこのアプリを確認していません」→ 詳細 → 移動 で OK。自分が作ったスクリプトなので問題なし)。
3. 下の **実行ログ** に `新しい API キー: xxxxxxxx…` が出るのでコピーしておく。
4. 同じプルダウンで **`authorize`** を選んで **▷ 実行** → 承認画面が出たら許可。
   ログに `OK: 見出し一致。次の記録は N 行目に入ります` と出れば OK (シートには何も書き込みません)。

> **4 を飛ばすと、接続テストは OK なのに記録だけ失敗します。**
> Web アプリ経由では承認画面を出せないため、シートへの書き込み権限はエディタで先に承認しておく必要があります。

キーはコードではなく **スクリプト プロパティ** (`API_KEY`) に保存されます。
コードを人に見せたり GitHub に上げたりしてもキーは漏れません。

### 3. Web アプリとしてデプロイ

1. 右上 **デプロイ → 新しいデプロイ**、種類の歯車で **ウェブアプリ** を選択。
2. 設定:
   - **次のユーザーとして実行**: 自分
   - **アクセスできるユーザー**: 全員
3. **デプロイ** → 表示された **ウェブアプリ URL** (`https://script.google.com/macros/s/…/exec`) をコピー。

> 「全員」にするのは、ブラウザの `fetch` からは Google ログインの Cookie を送れないためです。
> URL を知っていても **API キーがなければ何もできない** 作りにしてあります (下の「セキュリティ」参照)。

**コードを直したとき**は「新しいデプロイ」ではなく
**デプロイ → デプロイを管理 → 鉛筆 → バージョン: 新バージョン → デプロイ** にすると URL が変わりません。

### 4. アプリを置く

`fetch` と CSP (後述) の都合で `file://` 直開きではなく、HTTP で配信してください。

**A. PC だけで使う (いちばん手軽)**

```powershell
cd D:\streetfighter6_calc_machine\app
python -m http.server 8765 --bind 127.0.0.1
```

ブラウザで <http://127.0.0.1:8765/> を開く。

**B. スマホでも使う (おすすめ: GitHub Pages)**

1. このリポジトリの Settings → Pages → Source: **Deploy from a branch** → Branch: `main` / `(root)` → Save。
2. 1〜2 分後、<https://phanyle.github.io/streetfighter6_calc_app/app/> をスマホで開き、「ホーム画面に追加」。
3. 初回は設定画面で URL とキーを入れ直す (保存場所はサイトごとに別なので、ローカル版の設定は引き継がれない)。

> コードにキーは入っていないので公開リポジトリで OK。キーは各端末の中だけに保存されます。
> 同じ `<ユーザー名>.github.io` 上に他人のスクリプトを置かないこと (ブラウザ保存領域が同じオリジンで共有されるため)。

### 5. 初回設定

アプリを開くと設定画面が出るので、

- **Web アプリ URL**: 手順 3 の URL
- **API キー**: 手順 2 のキー

を入れて **接続テスト** → 「接続 OK」なら **保存**。
キャラ一覧・タグ一覧もここで自由に編集できます (1 行 1 項目)。

## 使い方

1. モード・自キャラを選ぶ (次回以降も記憶)。
2. 相手キャラをタップ → **勝ち / 負け** → (任意) ラウンド・ポイント・タグ・メモ。試したこと・対策・メンタルは折りたたみの中。
3. **記録する** (PC は `Ctrl+Enter`)。
4. 間違えたら 8 秒以内に出るトーストの **取り消し** で、いま追加した行を削除。

- 連戦を想定して、記録後も自キャラ・相手キャラ・ポイントは残ります。
- 右上に **今日の勝敗** と直近 10 戦の ●● が出ます (端末内の記録から集計)。
- 電波が切れているときは端末に保存し、つながったら自動で再送します (同じ試合が二重に入ることはありません)。

## セキュリティで気をつけたこと

### なぜ Tampermonkey ではなく単体ページにしたか

Tampermonkey でも作れますが、ユーザースクリプトは「表示中のサイトに自分のコードを差し込む」仕組みなので、
権限 (`@match` / `@connect` / `GM_xmlhttpRequest`) を少し広げただけで他サイト上でも動いてしまう、
スマホで使いにくい、という難点があります。
今回は **自分専用の小さなページ + 厳しい CSP** のほうが守る範囲が狭く、スマホでも使えるのでこちらにしました。

### サーバー側 (Apps Script)

| 対策 | 内容 |
|---|---|
| キーはコード外 | スクリプト プロパティに保存。`setupApiKey` 再実行で即ローテーション |
| 定数時間比較 | キーを SHA-256 してから比較し、応答時間からキーを推測されにくくする |
| 総当たり対策 | 認証失敗が 10 分で 10 回を超えると全リクエストを拒否 (`resetLock` で解除) |
| レート制限 | 正しいキーでも 1 分 30 件まで |
| 書き込み専用 | シートの中身を返す API はない。キーが漏れても **読まれない** |
| 入力チェック | 結果・ラウンド・モードは決まった値のみ、文字数上限、制御文字除去 |
| 数式インジェクション対策 | `=` `+` `-` `@` で始まる値は先頭に `'` を付けて文字列として保存 |
| 取り消しは直前の 1 行だけ | 書いた行がまだ最後の記録で、中身も書いたときのままの場合だけ空に戻す (6 時間以内)。過去データは消せない |
| 権限最小化 | `spreadsheets.currentonly` (このシートのみ) |
| エラー詳細を返さない | 詳細は Apps Script の実行ログにだけ残す |

### クライアント側 (アプリ)

| 対策 | 内容 |
|---|---|
| CSP | 通信先を `script.google.com` / `script.googleusercontent.com` のみに制限。外部スクリプト・インライン スクリプト禁止 |
| 外部ライブラリなし | サプライチェーン経由で乗っ取られる余地をなくす |
| XSS 対策 | 表示はすべて `textContent`。`innerHTML` 不使用 |
| 送信先チェック | URL が `https://script.google.com/macros/s/…/exec` 形式でないと保存も送信もしない (キーの誤送信防止) |
| キーは URL に載せない | POST 本文で送る。`credentials: 'omit'`、`Referrer` なし |
| 保存先を選べる | 「この端末にキーを保存する」をオフにするとタブを閉じた時点で消える |

### 運用のお願い

- キーは **パスワードと同じ扱い**。スクショや配信画面に映さない。
- 漏れたかも？と思ったら `setupApiKey` を実行 → 新しいキーを各端末に入れ直す。古いキーはその瞬間に無効。
- 共有 PC では「この端末にキーを保存する」をオフに。
- スプレッドシート自体の共有設定は今まで通りで OK (Web アプリは「自分」として動くので、シートを公開する必要はない)。

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| 「送信できませんでした」「通信できません」/ オンラインなのに「未送信 N 件」が残る | ほぼデプロイ設定。「アクセスできるユーザー」が **全員** 以外 (「Google アカウントを持つ全員」も NG) だとログイン画面へ飛ばされブラウザが遮断する → デプロイを管理 → ✏ → 全員 + 新バージョン。URL が `/exec` で終わるかも確認 |
| 接続テストは OK なのに記録だけ失敗 / 実行数で doPost が「失敗しました」 | シートへの書き込み権限が未承認。エディタで `authorize` を実行して許可する |
| 「応答が JSON ではありません」 | デプロイの「アクセスできるユーザー」が「全員」になっていない / URL が `/dev` になっている → `/exec` の URL を使う |
| 「API キーが違います」 | キーのコピーミス。前後の空白に注意。`setupApiKey` を再実行したなら新しいキーを入れる |
| 「ロック中です」 | 認証失敗が続いた。キーを確認してから Apps Script で `resetLock` を実行 (10 分待っても解除) |
| コードを直したのに反映されない | 「デプロイを管理」から **新バージョン** を作る (保存だけでは本番 URL に反映されない) |
| 「通信エラー」でテストが通らない | `file://` で開いていないか確認。手順 4 の方法で配信する |
| 未送信が溜まったまま | 設定の URL / キーが正しいか確認。直れば次回起動時か通信復帰時に再送される |
| キャラが足りない | 設定の「キャラ一覧」に 1 行追加 |
